# 校园导览 Agent 核心体验流程

## 1. 产品体验定位

校园导览 Agent 是一个面向复旦校园的双入口 AI 导览 App。

它的核心不是由 AI 临时生成路线，而是基于团队提前设计好的校园路线，通过用户回答的问题判断最适合的路线，并在游览过程中提供伴随式 Agent 讲解与随时可拉起的问答能力。

整体体验可以概括为：

```text
用户回答问题
-> 系统匹配预设路线
-> 用户进入地图
-> 选择导览模式或自由探索
-> 在地图中随时拉起 chatbot 进行文字追问或拍照识图
```

## 2. 核心原则

### 2.1 路线是预设的，不是实时生成的

路线由产品团队提前设计，例如：

- 学术风路线
- 梦校风路线
- 公园风路线
- 校友怀旧路线
- 新生熟悉校园路线

用户回答身份、兴趣、时间、讲解偏好后，系统做的是路线匹配，而不是路线生成。

匹配方式可以是：

- 规则映射：根据选项直接匹配路线。
- AI 判断：让模型理解用户回答，并从已有路线中选择最合适的一条。

不论使用哪种方式，输出都必须落在已有路线集合内。

### 2.2 App 有两种主要模式

App 的主要模式是：

- 导览模式：用户按照推荐路线走，GPS 到点自动触发讲解。
- 自由探索模式：用户不跟随路线，自己闲逛，看到感兴趣的对象后主动提问或拍照识图。

两种模式不是能力隔离，而是主流程不同。

### 2.3 Chatbot 是可随时拉起的半层能力

Chatbot 不只属于自由探索模式。

在导览模式中，用户也可以随时从底部拉起 chatbot，进行：

- 当前点位追问
- 路线相关问题
- 拍照识图
- 讲解风格调整
- 附近地点询问

因此，拍照识图应该被理解为一种横向能力，而不是一个独立模式。

## 3. 信息架构关系

可以把体验拆成三层：

```text
底层能力：Agent 对话 + 拍照识图 + GPS 定位 + 知识库检索
中层模式：导览模式 / 自由探索模式
上层入口：画像问答、路线推荐、地图点位、半屏 chatbot
```

其中：

- 地图是主舞台。
- 预设路线是导览模式的主轴。
- Chatbot 是随时可拉起的交互层。
- 拍照识图是 chatbot 内的关键能力。
- 知识库是所有回答的内容基础。

## 4. 全局体验流程

### 4.1 首次进入

用户首次进入 App 后，先完成一组轻量问题，用于判断本次导览意图。

问题包括：

- 用户身份：新生、在校生、访客、校友、家长、交换生、高中生等。
- 兴趣方向：校史、建筑、校园生活、人文、自然、拍照、吃饭、运动等。
- 可用时间：15 分钟、30 分钟、1 小时、半日等。
- 讲解风格：轻松、有趣、严肃、学术、亲切、适合小朋友等。
- 语言偏好：中文、英文、中英双语。

完成后，系统根据回答匹配一条预设路线。

```text
用户回答问题
-> 系统解析用户画像和本次意图
-> 从预设路线中选择一条最合适的路线
-> 展示路线名称、路线说明、预计用时和点位顺序
```

### 4.2 进入地图首页

路线匹配完成后，用户进入地图首页。

地图首页应展示：

- 用户当前位置
- 推荐路线
- 路线点位顺序
- 当前推荐开始点
- 可进入导览模式的入口
- 可进入自由探索的入口
- 底部可拉起的 chatbot 入口

地图首页不是单纯地图，而是整个导览体验的主容器。

## 5. 导览模式流程

导览模式适用于用户接受推荐路线，并希望按照路线完成一次校园导览。

主流程：

```text
用户点击开始导览
-> 地图显示路线与点位进度
-> 用户沿路线行走
-> GPS 判断用户接近当前点位
-> 自动触发 Agent 讲解
-> 用户听完 / 看完讲解
-> 用户可追问或继续前往下一个点位
-> 系统更新路线进度
```

导览模式的核心体验是“低操作成本”。用户不需要每到一个点都主动点开介绍，系统应在合适时机自动触发讲解。

### 5.1 到点自动讲解

当 GPS 判断用户到达或接近某个路线点位时，系统自动触发该点位讲解。

讲解内容由以下上下文决定：

- 当前点位
- 当前路线
- 用户 profile
- 已完成点位
- 导览员 Agent 风格
- 当前语言偏好

### 5.2 讲解后的追问

Agent 完成讲解后，用户可以继续追问。

追问可以包括：

- “这里有什么历史？”
- “能不能讲轻松一点？”
- “附近还有什么值得看？”
- “这个地方和复旦校史有什么关系？”
- “适合拍照的位置在哪里？”

追问发生在当前点位上下文中，系统回答时应优先结合当前点位和当前路线。

### 5.3 导览模式中的 chatbot 半层

导览过程中，用户可以随时从底部拉起 chatbot。

这个半层可以支持：

- 文字提问
- 拍照识图
- 当前点位追问
- 路线进度询问
- 下一个点位询问
- 附近地点推荐

流程：

```text
导览进行中
-> 用户拉起 chatbot 半层
-> 用户输入文字或拍照
-> 系统结合当前路线、当前点位、GPS 和知识库回答
-> 用户收起 chatbot
-> 回到路线导览
```

这里的 chatbot 是导览模式的辅助层，不会中断路线状态。

## 6. 自由探索模式流程

自由探索模式适用于用户不想跟随固定路线，而是自己在校园中闲逛。

主流程：

```text
用户进入自由探索
-> 地图显示当前位置和附近点位
-> 用户自由移动
-> 用户看到感兴趣的建筑、牌匾、展板或景观
-> 拉起 chatbot
-> 拍照或文字提问
-> 系统结合照片、GPS、附近候选点位和知识库回答
-> 用户继续追问或继续闲逛
```

自由探索模式的核心体验是“即时好奇心满足”。用户不需要先选择路线，也不需要到达指定点位，只要看到感兴趣的对象，就可以直接问。

## 7. 拍照识图能力

拍照识图是 chatbot 内的一种关键能力，在导览模式和自由探索模式中都可以使用。

识别逻辑：

```text
用户拍照
-> 图像识别照片内容
-> 获取当前 GPS
-> 匹配附近候选点位或对象
-> 检索校园知识库
-> 结合用户 profile 和当前模式生成回答
```

系统不应只依赖视觉模型判断对象，而应结合：

- 照片内容
- 用户当前位置
- 附近点位
- 当前路线状态
- 知识库

这样可以降低误识别和模型幻觉风险。

## 8. 不同模式下的 Agent 上下文

同一个 Agent 能力在不同场景中使用不同上下文。

| 场景 | Agent 主要上下文 |
| --- | --- |
| 导览模式自动讲解 | 当前路线、当前点位、用户 profile、导览员风格、路线进度 |
| 导览模式 chatbot | 当前路线、当前点位、GPS、已讲解内容、用户 profile |
| 自由探索 chatbot | 当前 GPS、附近候选点位、照片内容、用户 profile |
| 点位页追问 | 当前点位、当前讲解内容、用户 profile |
| 拍照识图 | 照片内容、当前位置、附近点位知识库、当前模式 |

## 9. MVP 应优先打通的主链路

MVP 阶段建议优先完成两条链路。

### 9.1 导览模式链路

```text
回答问题
-> 匹配预设路线
-> 展示地图和路线
-> 开始导览
-> GPS 到点触发讲解
-> 用户追问
-> 继续下一个点位
```

### 9.2 自由探索链路

```text
进入自由探索
-> 拉起 chatbot
-> 拍照识图或文字提问
-> 结合照片、GPS 和知识库回答
-> 用户追问
```

### 9.3 导览中的半层问答链路

```text
导览进行中
-> 拉起 chatbot
-> 文字问 / 拍照问
-> 结合路线、当前点位、GPS 和知识库回答
-> 收起 chatbot
-> 回到导览进度
```

## 10. 一句话总结

这个 App 的核心体验是：用户先通过问题匹配到一条预设校园路线，在导览模式中按路线行走并由 GPS 到点自动触发讲解；同时，用户可以在任意时刻拉起 chatbot 进行追问或拍照识图。自由探索模式则弱化路线，让用户边逛边拍、边问边听。
